# 深海载人舱 · 应急供氧歧管接头复原

更换应急供氧歧管的可拆模块后，在浏览器中录入模块格网（2–3 行 × 2–4 列）、
每格 2–3 个候选接头方案（唯一进气边、唯一出气边、改装负担）以及格网外缘的
气源端 / 用气端。点击「复原」后，应用**完全在本地**联合选择全部模块方案，
找到并展示总负担最小的合规复原，或在不存在合规组合时指出按格网顺序最早失效的
接头 / 导致回路的路径证据，并原样保留草稿。

## 合规复原的硬约束

1. **共享边严格“出气 → 进气”**：相邻格同开一条边时，必须一侧为出气、另一侧
   为进气；同出（气流对顶）或同进（双向等气）均判失败——从结构上杜绝把气源
   误接回自身。
2. **所有开启端口恰好配对**：内部边要么双侧齐闭，要么齐开且方向相反；格网
   外缘边只有登记了端子才能开启。
3. **每个登记端子都参与**：气源由外部注入歧管，所在边必须是该格的**进气边**；
   用气端所在边必须是**出气边**。
4. **全网只允许无环的气源 → 用气端路径**：逐格沿唯一出气边追踪，检测闭合回路、
   路径汇合、未送达用气端与游离管段；全部登记气源必须送达指定用气端。

## 本地开发（无需任何依赖，Node ≥ 20）

```bash
npm test       # node:test 单元/随机穷举交叉测试
npm run build  # 零依赖打包到 dist/（产物名带内容哈希）
npm start      # 启动静态服务（默认 8080，无 dist 时回退源码直供）
npm run healthcheck   # 对运行中的服务做 /healthz HTTP 探测
npm run smoke         # 启动 dist 服务并执行典型歧管复原冒烟
```

## Docker

```bash
# 可配置宿主机端口发布带健康检查的前端
MANIFOLD_HOST_PORT=9090 docker compose up -d --build web
# 浏览器访问 http://localhost:9090

# 一次性门禁服务：代码测试 → 生产构建 → 健康 HTTP 探测 → 复原冒烟，按退出码结束
docker compose up --build verify
```

- `web`：多阶段构建的运行时镜像（仅含 `dist/` 与零依赖静态服务器），
  容器内固定 8080，宿主机端口由 `MANIFOLD_HOST_PORT`（默认 8080）配置；
  镜像内置 `HEALTHCHECK` 探测 `GET /healthz`。
- `verify`：等待 `web` 健康后执行 `scripts/verify-pipeline.sh`，四步全过
  退出码 0，任一步失败即非零退出（`restart: "no"`，纯一次性服务）。

健康端点：`GET /healthz → 200 {"status":"ok",...}`。

## 目录

```
src/solver/model.mjs     录入模型规范化与校验（格网、方案、端子）
src/solver/validate.mjs  给定方案组合的配对/方向/端子/无环全量校验
src/solver/search.mjs    回溯联合选择（传播剪枝 + 最优负担）与不可行证据
src/render.mjs           格网/接头/端子/路径的 SVG 渲染
src/app.mjs              浏览器编辑器、本地求解调度、结果与草稿保留
scripts/                 构建、静态服务、健康探测、冒烟与 verify 流水线
tests/                   node:test 测试（含 60 组随机模型 vs 穷举核验）
```

## 不可行时的证据策略

- **接头级（优先）**：对每条内部边枚举相邻格的全部候选方案对、对每条外缘边枚举
  本格全部候选；若该边在所有局部选择下都无法合法配对，则它与全网其他选择无关、
  必然失效，取格网顺序（行优先，N→E→S→W）最早者在图中红圈标注。
- **回路级**：若每条边局部都存在配对可能、但无全局组合，则必为结构性冲突，
  报告沿唯一出气边走出的闭合回路链（或汇合 / 未达用气端的路径证据）。
- 无论哪种失败，编辑器草稿（含 localStorage 自动保存）均原样保留。
